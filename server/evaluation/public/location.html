How scores are calculated
Within 500 m — higher is better
Valid-address cases returned within 500 m of the reference ÷ all valid-address cases. Failed lookups remain in the denominator. During a run, unprocessed cases are not yet passes.
Lookup success
Cases returning coordinates ÷ all cases. Includes invalid test addresses, so a high score alone does not mean good quality.
False acceptance — lower is better
Deliberately invalid addresses returning coordinates ÷ all deliberately invalid addresses. N/A when none are provided.
Correct rejection — higher is better
Invalid addresses rejected as unresolved ÷ all invalid addresses. Provider failures do not count as rejections.
Median distance error
The middle straight-line distance error among positive cases that returned coordinates. Failed lookups are excluded here and counted in accuracy instead.
Average response time
Total lookup time ÷ processed cases, including failed lookups.

Uses the same verifyServiceAddress function as the product. No LLM judge, database writes, provider searches, or telephone calls. The map-pin choice flow is tested separately by npm run test:location.
